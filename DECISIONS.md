# Decision log

Why things are the way they are. These were deliberate choices (several from a two-architect
design debate on 2026-07-09, recorded in [PLAN.md](PLAN.md)) — don't reverse them in passing.
If one truly needs revisiting, ask the owner first.

| # | Decision | Why |
|---|---|---|
| D1 | **Foundation-first core, vertical slices after** — engine + data layer built and tested before any screen; every later migration ships together with the UI that reads it | The completions log is append-forever (no hard delete): wrong rows written early can never be cleaned up. Once the core was proven, runnable milestones beat big-bang phases |
| D2 | **expo-sqlite async API + `withExclusiveTransactionAsync` for XP writes** | Completion insert and character XP/level update must be atomic; the exclusive variant prevents statement interleaving |
| D3 | **UUIDs via `expo-crypto` `randomUUID()`** | Already in the Expo SDK — zero added install size, no `uuid` package or Hermes polyfill risk |
| D4 | **Local-time day keys, computed only in `src/engine/time.ts`** | `toISOString().slice(0,10)` shifts late-evening completions to the wrong day (UTC bug); ms-based day math breaks on DST. Centralizing makes the bug class un-writable |
| D5 | **Hand-rolled calendar (pure `monthGrid` + Pressable grid)** | `react-native-calendars` adds real bundle weight and fights the glow theme; a month grid is ~40 lines of tested pure code |
| D6 | **Migration 0001 contains ONLY Phase 1 tables** | Migrations are forward-only and immutable once shipped; guessing Phase 2/3 shapes early would freeze mistakes. Phase 2/3 tables arrive with their features, informed by tested engine code |
| D7 | **Stores may only `set()` from rows returned by query functions** | Structurally enforces write-to-DB-first (CLAUDE.md §3) — you cannot update UI state that wasn't persisted |
| D8 | **XP computed by callers (store→engine), passed into `logCompletion`** | Keeps queries thin and mechanical; all game math stays in the unit-tested engine |
| D9 | **Skips in their own table, not zero-XP completions** | `completions` keeps meaning "things done"; stats never need filter clauses; streak engine (Phase 2) reads completions alone (spec §4) |
| D10 | **`__DEV__` invariant: `character.total_xp === SUM(xp_awarded)` after every write** | The one derived-cache exception in the spec gets a tripwire so drift is caught at the write that caused it |
| D11 | **Due dates as YYYY-MM-DD text input + snooze as +1d/+1w buttons; no datepicker dependency** | Meets the §4 snooze requirement (push forward without touching history) at zero dependency cost. Revisit only if the owner wants a picker |
| D12 | **Default expo-router tab icon font stubbed via metro config; inline SVG icons instead** | ~1MB install-size saving; spec mandates inline SVG iconography and forbids icon-font packages (§5) |
| D13 | **Undo = delete a specific completion row and subtract exactly its `xp_awarded`** | Log-time XP decisions (esp. counted tasks) make undo trivially exact; no recomputation, no retro-adjust on target edits (§7) |
| D14 | **`.npmrc` legacy-peer-deps; jest pinned to 29** | Not choices — forced by the Expo SDK 57 ecosystem (see GOTCHAS.md 1–2). Revisit on SDK upgrade |
| D15 | **The web build (installable PWA) is now the primary distribution channel; the APK path stays supported but is no longer how the owner gets the app** | The self-built APK never worked on the owner's device, and every fix cycle needed a laptop, a 93MB sideload, and "allow unknown apps". A URL updates itself and installs to the home screen in two taps. Same codebase — `app/` and `src/` are untouched by platform |
| D16 | **Kept expo-sqlite on web (WebAssembly + OPFS) rather than swapping in a web storage layer** | One data layer, one migration runner, one set of queries, one XP invariant — a second storage backend would fork the thing the whole app's correctness rests on. Cost is the cross-origin-isolation requirement, which D17 absorbs |
| D17 | **Cross-origin isolation supplied by our own service worker, not by host headers** | SQLite-wasm needs `SharedArrayBuffer`, which needs COOP/COEP response headers, which GitHub Pages cannot set. A ~70-line worker re-serves same-origin responses with those headers — and doubles as the offline cache, so hosting stays free and account-free. `public/_headers` still covers hosts that can set headers |
| D18 | **Web export uses `output: "static"`, not `"single"`** | `app/+html.tsx` (PWA metadata, worker registration, no-flash dark background) is only honored under static rendering. It also pre-renders each route, so a cold load paints a themed spinner instead of a blank page |
| D19 | **Exclusivity on web rebuilt in JS (`src/db/transaction.ts`), never by downgrading to `withTransactionAsync`** | Web has no `withExclusiveTransactionAsync` (one shared worker connection). Plain transactions would keep atomicity but drop non-interleaving, which is exactly what the D10 XP invariant depends on. A promise chain restores it without weakening native, which still uses the real exclusive transaction |
| D20 | **Expo removed entirely; web-only React + Vite + Tailwind + Magic UI** (2026-08-02, owner's call) | The owner wanted Magic UI components usable "as is". They are React-DOM + Tailwind + framer-motion and cannot render against React Native primitives, so keeping Expo would have meant maintaining two UIs for one app. Web was already the primary channel (D15), so native was dropped rather than duplicated. §2 is untouched: still offline-first, no accounts, no backend |
| D21 | **The rewrite replaced `app/` and `src/components/` only — `src/engine/`, `src/types/`, `src/store/`, and every SQL statement moved unchanged** | This is the §3 "hard rule" (all game math is pure TypeScript, no framework imports) paying for itself: a total UI-framework change touched none of the correctness-critical code, and all 63 engine tests passed on the new runner without edits |
| D22 | **A `SqlDatabase` interface (`src/db/sqlite.ts`) mirroring the four expo-sqlite methods actually used** | Every file in `db/queries/` and `db/migrations/` kept compiling across a total driver swap; only `client.ts` changed. Keeping the old method names is deliberate — the point is that the seam, not the vocabulary, is what matters |
| D23 | **`opfs-sahpool` VFS in a dedicated worker, replacing the plain `opfs` VFS** (supersedes D17) | Plain OPFS reaches its worker over `SharedArrayBuffer`, which requires cross-origin isolation, which requires COOP/COEP headers GitHub Pages cannot set — the whole reason D17's service worker had to forge them. sahpool uses synchronous access handles instead and needs no isolation at all, so that entire workaround is deleted. It must run in a worker regardless, because `createSyncAccessHandle()` is worker-only |
| D24 | **`base: '/lifequest/'` unconditionally in `vite.config.ts`, not `command === 'build'`** | Making it build-only meant `vite preview` served at `/` while the built HTML requested `/lifequest/…`; the SPA fallback answered those asset requests with `index.html` and the app booted to a silent blank page. One path everywhere means dev, preview, and production agree on the router basename, the service-worker scope, and every asset URL |

| D25 | **React Router 8 (package `react-router`, not `react-router-dom`), React pinned up to 19.2.8** | `npm audit` flagged a high-severity advisory covering react-router 7.12.0–8.2.0 (RSC-mode CSRF). It does not apply here — no server, no RSC, no actions — but there is no patched 7.x, so the choice was "ship a red audit" or upgrade. v8 drops the `react-router-dom` package entirely (imports move to `react-router`) and requires react ≥19.2.7, making this a three-package change. Taken because only the stable declarative API is used (`BrowserRouter`, `Routes`, `Route`, `NavLink`, `Link`, `useNavigate`, `useParams`, `useLocation`), the React bump is patch-level within 19.2.x, and the full browser harness re-verified every route, deep link, and the two-tab case afterwards. `npm audit` is now clean |

**Superseded by the 2026-08-02 web rewrite (D20):** D2, D3, D12, D14, D16, D17, D18, D19 were all
Expo/React-Native-specific and no longer describe the code. They are kept for the reasoning, not as
current guidance. The XP-write invariant they protected (D10) is intact — `src/db/transaction.ts`
still serializes every write, now because the sahpool VFS is single-connection.
